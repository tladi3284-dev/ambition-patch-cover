## Ⅴ. 기본 작업 범위

### 1. 확인된 원본 게임 폴더

사용자가 제공한 Google Drive 폴더는 게임 원본 파일이 보관된 원본 게임 폴더로 확인되었다.

```

SOURCE_GAME_ROOT
├─ BGM
├─ Cursor
├─ HTML
├─ MOVIE
├─ SE
├─ grp
├─ map
├─ msg
├─ scenario
├─ trial
├─ Nobunaga11WPK.exe
├─ Nobunaga11WPK_Launcher.exe
├─ Nobunaga11WPK.pdf
├─ graphres.bin
└─ 기타 원본 파일
```

위 폴더 안의 `msg`와 `grp`는 한글패치 배포 폴더가 아니라 게임 원본 데이터 폴더이다.

확인된 원본 게임 폴더 안에는 `nobu11_한글패치`와 같은 별도의 한글패치 전용 폴더가 현재 존재하지 않는다.

### 2. 최초 활성 범위

프로젝트는 원본 게임 폴더의 `msg` 폴더에 들어 있는 메시지 파일부터 시작한다.

```

SOURCE_GAME_ROOT\msg\*.n11
```

초기 단계에서는 필요한 일본어 문구를 자연스러운 한국어로 번역하고, 원본과 분리된 작업 사본을 재구성한 뒤 별도의 한글패치 배포 폴더에 결과 파일만 저장한다.

### 3. 원본 폴더 보호 원칙

- Google Drive의 원본 `msg` 파일을 직접 편집하지 않는다.
- Google Drive의 원본 `grp` 파일을 직접 편집하지 않는다.
- 원본 파일은 읽기·목록 확인·해시 계산·작업 사본 생성의 기준으로만 사용한다.
- 번역, 재구성, 시험 적용은 원본과 분리된 작업공간에서 수행한다.
- 배포용 수정 파일은 별도의 `nobu11_한글패치` 폴더에서 관리한다.
- 백업 파일은 별도의 `backup` 폴더에서 관리한다.

### 4. 초기 단계 수정 제외 대상

MSG 우선 단계에서는 다음 파일을 수정하지 않는다.

```

grp\FONT.N11
grp\FONT12.N11
Nobunaga11WPK.exe
Nobunaga11WPK_Launcher.exe
기타 grp 파일
기타 데이터 파일
Steam 관련 파일
실행 보호 관련 파일
```

### 5. 조건부 폰트 작업

MSG 작업만으로 중요한 문구를 정상적으로 표시할 수 없는 경우에만 다음 파일의 작업 사본을 검토한다.

```

grp\FONT.N11
grp\FONT12.N11
```

폰트 작업은 전체 MSG 작업이 끝난 뒤 보류 항목을 재검토하는 마지막 단계에서 사용자 승인 후 제한적으로 수행한다.

### 6. 기타 파일

다른 파일은 일본어 잔존이나 표시 오류의 직접 원인으로 확인된 경우에만 개별적으로 검토한다.

추가 파일은 자동으로 작업 범위에 포함하지 않으며, 원본 폴더의 존재만으로 수정 대상이라고 판단하지 않는다.

```
豊臣秀吉 → 도요토미 히데요시
徳川家康 → 도쿠가와 이에야스
武田信玄 → 다케다 신겐
上杉謙信 → 우에스기 겐신
伊達政宗 → 다테 마사무네
```

### 2. 사용하지 않는 표기

```

織田信長 → 직전신장
豊臣秀吉 → 풍신수길
徳川家康 → 덕천가강
武田信玄 → 무전신현
```

### 3. 인명 순서

일본 인명은 성과 이름 순서를 유지한다.

```

오다 노부나가
도요토미 히데요시
도쿠가와 이에야스
```

다음처럼 순서를 바꾸지 않는다.

```

노부나가 오다
히데요시 도요토미
이에야스 도쿠가와
```

### 4. 일반 용어와의 구분

인명과 지명은 일본어 발음에 따라 표기하지만 메뉴, 명령, 설명과 일반 용어는 자연스러운 한국어로 번역한다.

```

出陣 → 출진
降伏 → 항복
同盟 → 동맹
停戦 → 휴전
内政 → 내정
外交 → 외교
兵糧 → 군량
褒美 → 포상
```

## Ⅸ. MSG 구조 보존 원칙

MSG 파일을 수정할 때 다음 요소를 보존한다.

- 메시지 ID
- 메시지 순서
- 포인터 관계
- 제어 코드
- 플레이스홀더
- 내부 식별자
- 메시지 종료 구조
- 대상 외 메시지
- 번역하지 않는 원시 데이터

번역문만 자연스러운 한국어로 변경하며, 파일을 읽는 데 필요한 내부 구조는 임의로 변경하지 않는다.

MSG 파일을 적용하기 전에 가능한 범위에서 다음을 확인한다.

- 재분석 가능 여부
- 포인터 범위 오류 여부
- 메시지 개수 유지 여부
- 제어 코드 보존 여부
- 대상 외 문자열 변경 여부

## Ⅹ. 항목별 최대 3회 시도 원칙

### 1. 적용 대상

- 특정 메시지
- 특정 MSG 파일
- 특정 화면
- 특정 글자 문제
- 특정 제어 코드 문제
- 특정 줄바꿈 문제
- 특정 재구성 실패

### 2. 1차 시도

```

원본 백업
→ 메시지 추출
→ 자연스러운 한국어 번역
→ 기존에 표시 가능한 문자 사용
→ MSG 파일 재구성
→ 수정 파일 적용
→ 게임 확인
```

### 3. 2차 시도

첫 번째 시도가 실패하면 확인된 원인과 직접 관련된 부분만 수정한다.

- 문장 길이 축소
- 줄바꿈 위치 변경
- 제어 코드 위치 복구
- 플레이스홀더 수정
- 문제 문자 치환
- 더 짧은 동의어 사용
- 메시지 종료 처리 수정
- 해당 메시지만 다시 적용

### 4. 3차 시도

두 번째 시도도 실패하면 마지막 최소 우회를 적용한다.

- 핵심 의미만 남긴 짧은 문장
- 문제가 있는 글자를 사용하지 않는 표현
- 안전한 단어로 교체
- 해당 메시지만 일본어 원문 유지
- 문제 메시지를 제외하고 나머지만 적용
- 부분 번역 상태로 적용

### 5. 동일 작업 반복 금지

이전 시도와 실질적으로 동일한 작업은 새로운 시도로 인정하지 않는다.

- 번역문 변경
- 사용 문자 변경
- 문장 길이 변경
- 제어 코드 수정
- 대상 범위 축소
- 재구성 방식 변경

## Ⅺ. 3회 실패 후 처리

## Ⅻ. 마지막 단계의 보류 항목 검토

### 1. 게임플레이 영향이 낮은 경우

- 해당 문구를 일본어 원문으로 유지
- 부분 미번역으로 유지
- 알려진 제한 사항에 기록
- 최종 배포를 막지 않음

### 2. 의미 이해가 가능한 경우

- 일부 비핵심 일본어 잔존
- 일부 장문 미번역
- 드물게 발생하는 특수문자 문제
- 의미를 이해할 수 있는 경미한 글자 문제
- 낮은 빈도의 표기 차이
- 일부 이미지의 일본어

### 3. 게임플레이에 중요한 경우

```

번역문 재조정
→ 안전한 문자로 치환
→ 더 짧은 표현 적용
→ 제한적 폰트 파일 수정 검토
→ 필요한 기술 연구만 재개
```

### 4. 게임 진행을 차단하는 경우

- 해당 번역 적용 취소
- 일본어 원본 메시지 사용
- 제한적 폰트 수정
- 해당 문제와 직접 관련된 기술 연구만 재개

게임 진행 가능 상태를 기술적 완전성보다 우선한다.

## ⅩⅢ. 조건부 폰트 작업

### 1. 진입 조건

해당 항목이 MSG 단계에서 3회 실패하였다.

원문 복원 후 보류 상태로 등록되었다.

자연스러운 표현 변경으로 해결할 수 없다.

해당 문구가 게임플레이에 중요하다.

문제의 원인이 글리프나 폰트일 가능성이 높다.

원본 백업과 복원 수단이 준비되어 있다.

사용자 승인을 받았다.

### 2. 기본 대상

```

grp\FONT.N11
grp\FONT12.N11
```

### 3. 수정 원칙

- 필요한 문자나 셀만 제한적으로 수정한다.
- 폰트 파일 전체를 불필요하게 재설계하지 않는다.
- 기존에 정상 표시되는 문자는 유지한다.
- 수정 전후 해시를 기록한다.
- 게임에서 해당 문제만 다시 확인한다.
- 실패 시 즉시 원본으로 복원한다.

## ⅩⅣ. 파일 교체형 한글패치 적용 방식

### 1. 용어 정의

본 프로젝트에서는 원본과 분리하여 만든 수정 파일을 게임 설치 폴더의 동일한 상대 경로에 복사하고, 동일한 이름의 대상 파일만 바꾸는 방식을 다음과 같이 부른다.

```

파일 교체형 한글패치
```

### 2. 폴더 역할 분리

```

SOURCE_GAME_ROOT: Google Drive의 원본 게임 폴더, 읽기 전용
WORKSPACE_ROOT: nobu11_작업공간, 번역·재구성·검증 준비용
BACKUP_ROOT: backup, 원본 및 직전 정상본 보존용
PATCH_ROOT: nobu11_한글패치, 사용자 적용용 수정 파일만 보관
LIVE_GAME_ROOT: Steam 게임 설치 폴더, 승인 후 검증 적용 대상
```

각 폴더는 목적이 다르므로 서로 대체하거나 혼용하지 않는다.

### 3. 확인된 현재 상태

```

SOURCE_GAME_ROOT_VERIFIED: true
SOURCE_MSG_FOLDER_VERIFIED: true
SOURCE_GRP_FOLDER_VERIFIED: true
DEDICATED_PATCH_FOLDER_PRESENT_IN_SOURCE_ROOT: false
SOURCE_FILES_MODIFIED: false
PATCH_APPLICATION_EXECUTED_UNDER_REVISION_2: false
```

현재 Google Drive 원본 폴더의 `msg`와 `grp`를 한글패치 폴더로 간주하지 않는다. 한글패치 폴더는 원본과 별도로 생성해야 한다.

### 4. 작업공간 및 초기 배포 구조

```

nobu11_작업공간\
├─ source_reference\          원본 목록·해시·경로 기록
├─ working\                   번역 및 재구성 작업 사본
├─ backup\                    원본 및 직전 정상본
├─ reports\                   배치별 결과 기록
└─ nobu11_한글패치\           사용자 적용용 배포본
   └─ msg\
      ├─ 수정파일01.n11
      ├─ 수정파일02.n11
      └─ 수정파일03.n11
```

폰트 파일이 승인되어 필요한 경우에만 배포 구조에 `grp`를 추가한다.

```

nobu11_한글패치\
├─ grp\
│  ├─ FONT.N11
│  └─ FONT12.N11
└─ msg\
   └─ 실제로 수정된 MSG 파일
```

### 5. 적용 원칙

- 게임 폴더 전체를 삭제하거나 교체하지 않는다.
- `msg` 또는 `grp` 폴더 전체를 삭제하거나 통째로 바꾸지 않는다.
- 한글패치에 실제 포함된 개별 파일만 복사한다.
- 동일한 상대 경로와 동일한 이름의 대상 파일만 교체한다.
- 한글패치에 포함되지 않은 파일은 그대로 유지한다.
- 대상 파일을 교체하기 전에 원본을 별도 백업한다.
- 승인된 파일 목록에 없는 파일은 변경하지 않는다.
- Google Drive 원본 게임 폴더에는 수정본을 덮어쓰지 않는다.

### 6. 수동 적용 절차

```

게임과 런처 종료
→ nobu11_한글패치 안의 실제 수정 파일 목록 확인
→ 게임 설치 폴더의 동일 이름 원본 파일 개별 백업
→ 수정된 개별 파일만 동일 상대 경로에 복사
→ 파일 크기와 SHA-256 확인
→ 승인된 게임 검증 수행
→ 실패하면 백업 원본으로 즉시 복원
```

### 7. 허용 파일 목록

초기 허용 범위:

```

INITIAL_ALLOWED_FILES:
  - msg/실제로_수정된_파일.n11
```

조건부 허용 범위:

```

CONDITIONAL_ALLOWED_FILES:
  - grp/FONT.N11
  - grp/FONT12.N11
```

위 목록은 원본 폴더 전체에 대한 변경 허용이 아니라, 승인된 작업 사본과 배포본의 개별 파일에만 적용된다.

## ⅩⅤ. 백업 및 복원

### 1. 적용 전 확인

- 게임 종료
- 런처 종료
- 대상 원본 파일 존재 여부
- Google Drive 원본 경로와 로컬 게임 경로 구분
- 원본 파일 크기
- 원본 SHA-256
- 지원 게임 버전
- 별도 백업 생성 여부
- 작업 사본과 배포본 경로
- 적용 파일 상대 경로
- 적용 파일 SHA-256

### 2. 백업 구조

```

nobu11_작업공간\backup\
├─ MSG_BATCH_001\
├─ MSG_BATCH_002\
├─ MSG_BATCH_003\
└─ FONT_FINAL_STAGE\
```

각 백업에는 다음 정보를 기록한다.

```

BATCH_ID:
SOURCE_ROOT:
ORIGINAL_RELATIVE_PATH:
ORIGINAL_FILE_NAME:
ORIGINAL_SIZE:
ORIGINAL_SHA256:
BACKUP_PATH:
BACKUP_TIME:
WORKING_COPY_PATH:
PATCH_OUTPUT_PATH:
CANDIDATE_SHA256:
```

### 3. 실패 후 복원

시도가 실패하면 다음 시도 전에 로컬 게임 설치 폴더의 대상 파일을 원본 또는 직전 정상 파일로 복원한다.

3회 실패한 경우 반드시 원본으로 복원한 뒤 해당 항목을 보류한다.

Google Drive 원본 파일은 복원 대상이 아니라 변경되지 않은 기준 원본으로 유지한다.

### 4. 복원 확인

- 원본 SHA-256 일치
- Google Drive 기준 원본과 백업본의 식별 정보 일치
- 게임 실행
- 대상 화면 접근
- 저장
- 불러오기
- 정상 종료
- 임시 파일 및 미승인 수정 파일 잔존 여부

## ⅩⅧ. 기술 연구 재개 조건

- 중요한 한국어 문자가 표시되지 않음
- 필수 메뉴나 명령을 MSG 수정으로 표현할 수 없음
- MSG 파일이 정상적으로 재구성되지 않음

- 제한적 폰트 수정이 반드시 필요함

기술 연구를 다시 시작할 때도 전체 과제를 재개하지 않는다.

해당 차단 문제를 해결하는 데 필요한 최소 범위만 수행한다.

## ⅩⅩⅣ. 최종 결론

프로젝트명은 `nobu11`로 한다.

기존 프로젝트와 지금까지의 연구·검증 자료는 폐기하지 않고 모두 보존한다.

사용자가 제공한 Google Drive 폴더는 게임 원본 파일이 보관된 원본 게임 폴더이며, 최상위에 `msg`, `grp`, `scenario`, `map` 등 게임 데이터 폴더와 실행 파일이 존재하는 것으로 확인되었다.

원본 게임 폴더 안의 `msg`와 `grp`는 한글패치 배포 폴더가 아니다. 현재 확인 범위에서는 별도의 `nobu11_한글패치` 폴더가 존재하지 않는다.

따라서 원본 Google Drive 파일을 직접 수정하거나 그 안의 `msg`와 `grp`를 배포 폴더로 사용하지 않는다.

앞으로의 작업은 원본과 분리된 `nobu11_작업공간`에서 수행하며, 원본 참조, 작업 사본, 백업, 보고서, 배포본을 서로 구분한다.

실제 작업은 최소한도 원칙에 따라 원본 `msg\*.n11`에서 1~3개 파일과 10~30개 메시지 정도의 작은 묶음을 선정하는 것부터 시작한다.

선정한 원본 파일의 경로, 크기, SHA-256을 기록하고 별도 백업과 작업 사본을 만든 뒤, 작업 사본만 번역·재구성한다.

완성된 수정 파일은 별도의 `nobu11_한글패치\msg` 폴더에 저장하며, 원본 폴더나 게임 폴더 전체를 복사하지 않는다.

게임에 적용할 때는 승인된 개별 수정 파일만 동일한 상대 경로와 동일한 이름의 원본 파일과 교체한다. 교체 전에는 반드시 로컬 게임 원본 파일을 백업하고, 실패하면 즉시 복원한다.

각 메시지·파일·화면 문제는 최대 3회까지만 시도한다. 첫 번째 시도는 표준 번역과 MSG 재구성, 두 번째 시도는 확인된 원인에 대한 제한적 수정, 세 번째 시도는 짧은 문장·안전한 문자·부분 원문 유지 등의 최소 우회 방식으로 진행한다.

3회 시도 후에도 해결되지 않으면 로컬 게임 파일을 원본으로 복원하고 해당 항목을 마지막 단계까지 보류한다. 보류 항목 때문에 전체 프로젝트를 중단하지 않고 적용 가능한 다른 MSG 작업을 계속한다.

폰트 파일 `grp\FONT.N11`과 `grp\FONT12.N11`은 MSG 단계의 중요 항목이 3회 실패하고 자연스러운 표현 변경으로도 해결할 수 없으며 사용자 승인을 받은 경우에만 작업 사본을 제한적으로 검토한다.

일본 인명은 `오다 노부나가`, `도요토미 히데요시`, `도쿠가와 이에야스`처럼 일본어 발음을 기준으로 자연스럽게 표기한다.

메뉴, 명령, 설명과 대사는 일본어를 기계적으로 읽는 방식이 아니라 한국어 사용자가 기능과 상황을 이해할 수 있도록 자연스럽게 번역한다.

모든 일본어의 100% 제거, 모든 글리프 해결, 모든 내부 구조 규명은 필수 조건이 아니다.

게임을 하는 사람이 화면의 한국어를 보고 메뉴와 명령을 이해하며, 내정·전투·외교를 진행하고, 저장과 불러오기를 정상적으로 사용할 수 있으면 충분하다.

다음 조건을 충족하면 `nobu11` 프로젝트는 실사용 가능한 자연 한국어 한글화 목적을 달성한 것으로 판단한다.

- 게임이 정상적으로 실행되는가?
- 한국어를 보고 주요 기능을 이해할 수 있는가?
- 게임을 실제로 계속 진행할 수 있는가?
- 인명과 지명을 알아볼 수 있는가?
- 저장과 불러오기가 정상적으로 작동하는가?
- 게임 진행을 막는 치명적인 오류가 없는가?
- 문제가 발생하면 원본으로 복원할 수 있는가?
- Google Drive 원본 파일이 변경되지 않은 기준 원본으로 보존되는가?
